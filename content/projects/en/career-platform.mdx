Satkom Career is the recruitment site of PT Satkomindo Mediyasa. Candidates browse openings, fill in one profile and apply in a click; the HR team reviews every applicant through the same standardized CV. Five of us built it during my internship from February to June 2024. This page is about my part of it.

## The problem

Applications used to arrive as CVs in every layout and file format, so comparing two candidates meant reading two very different documents. Several recruiters screened the same pool, and none of them could tell who had already read which CV.

## What the team built

- **Candidate site**: openings with search and filters, a multi-step profile with personal data, education, experience, certifications and documents, one-click applications and a "my applications" page.
- **Admin dashboard**: statistics, job postings, applicants per job, the standardized CV, user management and master data.
- **API**: AdonisJS 6 with Lucid on MySQL, VineJS validation and access tokens for candidates and admins.

## My part

I wrote 177 of the frontend's 568 commits and 48 of the backend's 206, most of them in the admin side.

- **Auth and routing**: login, register and logout, auth state moved from hand-rolled code into a Zustand store, protected layouts with separate candidate and admin logins, and the 403 and 404 pages.
- **Admin dashboard**: summary cards, charts and applicant statistics, backed by aggregate queries I wrote in the API for applicants per job, totals and open positions.
- **Jobs and master data**: the job table with filters, posting, editing, deleting and status, job details with description and qualifications, the applicant list for each job, and the screens for departments, job levels, education degrees and notice periods.
- **Candidate profile**: profile sections, the multi-step edit form with validation and loading skeletons, and applying from a job's detail page.
- **Standardized CV**: a page that lays out a candidate's profile in the company's CV format, previews uploaded certificates with react-pdf and prints a PDF named after the job and the candidate.
- **Deployment**: the backend's Docker image, with nginx in front of the Node server.

## Challenges and how I solved them

### Two recruiters, one candidate

**Problem.** Recruiters screened the same applicants, and nobody could tell whether a CV had already been read.

**Solution.** Opening a CV logs the view once per recruiter. The applicant list shows who has read each CV and greys out the ones you have already opened, so every recruiter sees at a glance what is left to read.

### Balinese names broke the file paths

**Problem.** Uploaded documents were stored in a folder named after the candidate's first name, and Balinese first names such as "I Wayan" contain spaces, which broke the paths for anyone with a space in their name. Certificates, which are PDFs, were also saved with a .jpg extension.

**Solution.** Folder names strip whitespace on both the frontend and the API, and certificate files keep their real extension.

### A full name found nobody

**Problem.** First and last names live in separate columns, so a recruiter who typed a full name matched neither of them.

**Solution.** The search splits the query into words and matches each one against the first name, the last name and the two joined together.

### One CV for every candidate

**Problem.** HR wanted every CV in the same layout and printable, built from what candidates had already entered instead of yet another upload.

**Solution.** The CV is rendered in the browser from the profile data candidates already entered, with their certificates embedded, and printed with react-to-print. The file name is set from the job and the candidate's name, so downloaded CVs are easy to file.

## Lessons learned

- Test with real names. A space in a first name is normal in Bali, and it broke the file paths.
- Search the way people type. Recruiters type full names, so the query has to span columns.
- Small coordination features matter. One table and two endpoints told every recruiter which CVs were already read.
- Generate documents from data instead of collecting them. Standardizing the input made the output consistent for free.
